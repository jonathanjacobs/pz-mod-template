# Architecture decision records

Create an ADR when a consequential technical decision has realistic alternatives and should remain understandable after the immediate implementation work is over.

Use a numbered filename such as `ADR-001-short-decision-name.md`. Include context, decision, consequences, alternatives considered, and evidence/links. Do not create ADRs for routine implementation details.

## Index

Maintain a running list here as ADRs are added, one line each with its status (`Accepted`, `Rejected`, `Superseded`) and a short description. This gives an at-a-glance view of project decisions without opening every file.
