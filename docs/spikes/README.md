# Spikes

Use a spike for a bounded feasibility question or uncertain engine behavior. Name it `SPIKE-###-short-topic.md` and state the question, environment, procedure, evidence, outcome, and GO/NO-GO or next decision.

A spike is evidence, not a release claim. Promote supported conclusions into requirements, architecture, or an ADR when appropriate.

## Index

Maintain a running list here as spikes are added, one line each with its status (for example `Open`, `Closed successfully`, `Closed, rejected`, `Core question answered`). This gives an at-a-glance view of project state without opening every file.
